youvision/think-store

管理页如何工作

管理页读取 youvision/think-store 的查询接口，并用数据表格展示已安装的发布包；同步操作调用同一扩展的静态资源同步接口。

  • 部署流程
  • 接口与配置
  • 安全建议
  • 发布包：包名与包内 composer.json 的描述。
  • 版本：Composer 已安装版本。
  • 部署目标：由包内 project/project.json 的 path 计算出的相对路径，例如 public/store/store-example。
  • 部署项：project.json 中声明的部署条目数量。
  • 状态：已同步、未同步或异常；异常时可查看具体错误。
  • 操作：对单个包重新同步，或使用工具栏的“同步全部”批量处理。
  • 覆盖已有文件：勾选时覆盖同名文件；取消勾选时只补齐缺失文件。
  1. 主项目执行 composer require youvision/think-store，并允许 youvision/think-static 插件。
  2. 在 composer.json 的 extra.think-static.project_dir 中指向本包资源目录，用于部署管理页。
  3. 执行 composer dump-autoload，think-static 会把管理页部署到 public/store/think-store。
  4. 安装 youvision/think-store-example 等发布包后，在本页执行“同步全部”，把各包的静态资源部署到 public/store/{path}。
  5. 访问 /store/think-store/index.html 打开本管理页。

主项目配置示例：

{
  "extra": {
    "think-static": {
      "project_dir": "vendor/youvision/think-store/project"
    }
  }
}

如果主项目自身也有 project 目录，两者不能同时使用同一个 project_dir。可保留主项目自动部署，改为手动调用 think-static 的 StaticAssets 部署管理页，或通过反向代理把管理页单独映射到 public/store/think-store。

  • GET /store/packages：查询已安装的 youvision/think-store-* 发布包。
  • POST /store/packages/sync：重新同步全部发布包；传入 packages 时只同步指定包。
  • packages：包名、逗号分隔的包名或包名数组，可选。
  • force：是否覆盖同名文件，可选；缺省使用 config/store.php 的 force。
  • route.prefix：默认 store。修改后需同步调整本页 <main data-api="/store"> 的属性值。
  • prefix：默认 youvision/think-store-，决定哪些 Composer 包会被识别为发布包。
# 查询
curl http://127.0.0.1:8000/store/packages

# 同步全部
curl -X POST http://127.0.0.1:8000/store/packages/sync

# 同步指定包
curl -X POST http://127.0.0.1:8000/store/packages/sync \
     -d "packages=youvision/think-store-example"
  • 同步接口会写入 public/store，生产环境应通过中间件限制访问权限。
  • 建议只允许管理员或部署账号调用 POST /store/packages/sync。
  • 不要在公网环境暴露未鉴权的同步接口，避免静态资源被意外覆盖。
  • 修改 project 下的资源后，重新执行同步即可更新目标目录。
  • 发布包的 project.json 无效时不会中断其他包的同步，可在表格中查看错误详情。
